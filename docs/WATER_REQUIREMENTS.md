# ข้อกำหนดระบบประปา (Tabwater / PIOS)

สรุปจากโค้ดจริง (routes, controllers, models, ตาราง DB) ส่วนที่เป็นข้อสันนิษฐานมีหมายเหตุกำกับ

## 1. ภาพรวมและผู้ใช้

ระบบจัดการประปาหมู่บ้าน/อบต. แบบหลายหน่วยงาน (multi-tenant แยกด้วย `org_id_fk`) ครอบคลุมการจดมิเตอร์ ออกใบแจ้งหนี้ รับชำระเงิน ติดตามหนี้ค้าง ตัดมิเตอร์ และรายงาน

| บทบาท | สิทธิ์หลัก |
|---|---|
| super admin / admin | ตั้งค่าระบบทั้งหมด จัดการผู้ใช้ ปีงบประมาณ รอบบิล อัตราค่าน้ำ |
| finance staff | รับชำระเงิน ออกใบเสร็จ รายงานการเงิน |
| tabwater staff / ผู้จดมิเตอร์ (twman) | จดมิเตอร์ (เว็บ/มือถือ) ดูโซนที่รับผิดชอบ |
| ผู้ใช้ทั่วไป (LINE LIFF) | แจ้งเหตุประปา |

## 2. ข้อกำหนดเชิงหน้าที่ (Functional)

### FR-1 ข้อมูลผู้ใช้น้ำและมิเตอร์
`UserMeterInfosController`, ตาราง `tw_meter_infos`
- เพิ่ม/แก้ไข/ลบผู้ใช้น้ำ เพิ่มมิเตอร์หลายตัวต่อคน และนำเข้าแบบกลุ่ม (bulk)
- เก็บข้อมูลมิเตอร์: รหัส, เลขโรงงาน, ที่อยู่, โซน/ซอย, ประเภทมิเตอร์, วันที่ติดตั้ง, สถานะ (active/inactive), จำนวนงวดค้าง (`owe_count`), เลขอ้างอิงใบแจ้งหนี้
- ส่งออก Excel ดูรายชื่อตามซอย และดูประวัติการจดมิเตอร์

### FR-2 โซนและผู้จดมิเตอร์
`SubzoneController`, `UndertakerSubzoneController`
- จัดการโซน/ซอย และกำหนดผู้จดมิเตอร์ประจำซอย (`undertaker_subzones`)
- มีแดชบอร์ดบริการ/สถานะการจดแยกตามซอย

### FR-3 ปีงบประมาณและรอบบิล
`BudgetYearController`, `InvoicePeriodController`
- สร้างปีงบประมาณและรอบบิลรายเดือน (ชื่อรอบ, วันเริ่ม/สิ้นสุด, สถานะ)
- สั่งสร้างใบแจ้งหนี้ทั้งรอบ (`generateInvoice`)

### FR-4 การตั้งค่าอัตราค่าน้ำ
`MeterRateConfigController`, `TwPricingTypeController`
- กำหนดประเภทมิเตอร์และอัตราต่อประเภท โดยเลือกวิธีคิดได้ (`tier_calculation_type`)
  - อัตราก้าวหน้า (ขั้นบันได): หน่วยต่ำสุด–สูงสุด, ราคา/หน่วย, ลำดับขั้น (`tw_meter_type_rate_tiers`)
  - อัตราคงที่ต่อหน่วย (`fixed_rate_per_unit`)
- กำหนดค่ารักษามิเตอร์ขั้นต่ำ (`min_usage_charge`) พร้อมตัวเลือก `charge_min_only_zero_use` ให้คิดเฉพาะเดือนที่ใช้น้ำ 0 หน่วย
- กำหนด VAT, วันที่มีผล/สิ้นสุด และเปิด-ปิดการใช้งาน
- ตั้งค่าองค์กรและค่าตั้งต้นใบแจ้งหนี้/VAT ได้ (`SettingsController`)

### FR-5 การจดมิเตอร์
`InvoiceController`, `StaffMobileController`, `TwManMobileController`
- จดรายซอยผ่านเว็บ (`zone_create`, `zone_edit`, `zone_update`) หรือมือถือ
- มือถือถ่ายรูปมิเตอร์ แล้วประมวลผลภาพ (`process_meter_image`) เพื่อช่วยอ่านค่า
- ค่าที่เก็บ: เลขก่อน (`lastmeter`), เลขปัจจุบัน (`currentmeter`), หน่วยที่ใช้ (`water_used`)
- แก้ไขย้อนหลัง ลบ (สถานะ `deleted`) และดูผู้ใช้ที่ยังไม่จด
- วงจรสถานะใบแจ้งหนี้: **init → invoice → paid** (ค้างชำระ = **owe**, ยกเลิก = **deleted**)

### FR-6 การออกใบแจ้งหนี้
`InvoiceController`, ตาราง `tw_invoice`
- คำนวณ: `ยอดรวม (totalpaid) = ค่าน้ำ (paid) + VAT (vat) + ค่ารักษามิเตอร์ (reserve_meter)` และเก็บยอดยกมา (`previous_balance`)
- พิมพ์ใบแจ้งหนี้เดี่ยว/หลายใบ (`print_invoice`, `print_multi_invoice`) และส่งออก Excel รายโซน/รอบ
- ดูรายการที่ออกแล้ว (`invoiced_lists`)

### FR-7 การรับชำระเงิน
`PaymentController`, ตาราง `tw_acc_transactions`
- ค้นหาผู้ใช้/ซอย แล้วรับชำระรวมหลายใบแจ้งหนี้ใน 1 รายการ (เก็บ `paidsum`, `vatsum`, `reserve_meter_sum`, `totalpaidsum`, `cashier`)
- ชำระตามเลขใบแจ้งหนี้ (`store_by_inv_no`) ดูประวัติ ลบ/ยกเลิกการรับเงิน (`destroy`)
- พิมพ์ใบเสร็จและประวัติใบเสร็จ

### FR-8 หนี้ค้างและหนังสือแจ้งเตือน
`OwePaperController`
- ดึงรายชื่อผู้ค้างชำระ และพิมพ์ได้ 2 แบบ
  - ใบแจ้งหนี้ค้างชำระ (มีช่องลงนามผู้รับเงินและผู้อำนวยการกองคลัง)
  - หนังสือแจ้งเตือนแบบตราครุฑ
- `owe_count` เป็นฐานของกระบวนการตัดมิเตอร์

### FR-9 การตัด/ติดตั้งมิเตอร์คืน
`CutmeterController`, ตาราง `tw_cutmeter`
- รายชื่อผู้ที่มี `owe_count ≥ 2` เข้าสู่กระบวนการ โดยเก็บความคืบหน้าเป็น JSON (ใคร ทำอะไร เมื่อใด)
- สถานะ: init → cutmeter → install → complete (หรือ cancel)
- เมื่อตัดมิเตอร์ ระบบตั้งมิเตอร์เป็น inactive และบันทึกยอดค้างเป็น owe
- การติดตั้งคืนทำได้เมื่อเคลียร์ยอดค้างแล้ว (โค้ดตรวจ `owe_count` แต่เกณฑ์ไม่สอดคล้องกัน คือ 2 กับ 3 ต้องยืนยัน)
- พิมพ์เอกสารติดตั้งมิเตอร์ (`print_install_meter`)

### FR-10 รายงาน
`ReportsController`, `WaterLedgerController`
- ค้างชำระ (owe), สมุดบัญชี (ledger), ปริมาณน้ำที่ใช้, รับเงินรายวัน, ประวัติการจดมิเตอร์
- รายงาน ป.17 (`p17Report`) และส่งออก Excel

### FR-11 แจ้งเหตุประปา
`NotifyController`, ตาราง `tw_notifies`
- ผู้ใช้แจ้งผ่านฟอร์ม LINE LIFF พร้อมชื่อ เบอร์ ประเภทเหตุ รายละเอียด พิกัด รูป
- มีการตรวจสมาชิก หน้าสำเร็จ และแจ้งเตือนหัวหน้า/เจ้าหน้าที่ผ่าน LINE (`TwNotifyStaffs`)

### FR-12 โรงผลิตน้ำ ท่อ และอุปกรณ์
`TabwaterStation/Device/Pipeline/PipeNode/GisController`
- CRUD โรงผลิต อุปกรณ์ เส้นท่อ และจุดต่อท่อ (node)
- แผนที่ GIS (Leaflet) วาดตำแหน่งโรงผลิต/ท่อ/node และเก็บบันทึกอุปกรณ์/คุณภาพน้ำ (`TabwaterDeviceLog`, `TabwaterQualityLog`)
- แดชบอร์ดการผลิต: บันทึกคุณภาพน้ำ และเปิด-ปิดอุปกรณ์ (`TabWaterProductionDashboardController`, `TabwaterControlController`)

### FR-13 ย้ายข้อมูลเก่า
`TransferOldDataToNewDBController` ย้ายข้อมูลจากระบบเดิม (มีฟิลด์ `old_meter_id`, `old_inv_p_id`)

## 3. ข้อกำหนดที่ไม่ใช่เชิงหน้าที่ (Non-functional)

- **Multi-tenant:** ทุกข้อมูลแยกตามองค์กร (`org_id_fk`) และเลือกองค์กรที่ active ได้
- **สิทธิ์:** ใช้ role-based (Spatie) แยกตามกลุ่มเมนู
- **ภาษา/รูปแบบ:** ภาษาไทย ปี พ.ศ. พิมพ์ได้บน A4
- **มือถือ:** หน้าจดมิเตอร์ใช้งานบนมือถือได้ ผู้ใช้ปลายทางใช้ LINE LIFF
- **Stack:** Laravel 9, PHP 8.2, MySQL

## 4. ช่องว่างและข้อควรยืนยัน

1. เกณฑ์ตัดมิเตอร์ที่ใช้งานจริง: ค้าง 2 งวด หรือ 3 งวด (โค้ดไม่ตรงกัน)
2. สถานะ `owe` ถูกตั้งตอนไหน: โค้ดกำหนดตอนปิดรอบ/ตัดมิเตอร์ ควรยืนยัน flow
3. การเชื่อมประปากับ Smart Utility และตำแหน่งมิเตอร์ใน GIS (เลื่อนไว้ก่อน)
4. ยังไม่มีการชำระออนไลน์/QR และยังไม่เห็นการแจ้งเตือนอัตโนมัติผ่าน LINE สำหรับใบแจ้งหนี้ (มีเฉพาะเรื่องแจ้งเหตุ)
